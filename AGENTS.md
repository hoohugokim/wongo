# AGENTS.md — wongo

wongo (원고, “manuscript”) is a Python ≥3.11 package and CLI for verified
Quarto-to-journal DOCX pipelines. The engine is post-v0.1.0 and behavior-pinned
against a private reference manuscript; the uplift records live in `plans/archive/`.

## Session start

- Read `HANDOFF.md`, then `TASKS.md`, then only ROADMAP's agent-visible milestone.
- Read `DECISIONS.md` before reopening architecture, tooling, or policy choices.
- Preserve unfamiliar and uncommitted work; agents share this workspace.

## Commands

- Setup: `uv sync --all-extras`
- Test: `uv run pytest -q`
- Lint: `uv run --with ruff ruff check --ignore EXE001,DTZ011 src/wongo tests tools`
- Build: `uv build`
- CLI smoke: `uv run wongo --version && uv run wongo profile verify est --offline`
- Setup check on a machine: `uv run wongo doctor` (Quarto, R, packages, project config)
- Render parity (requires `WONGO_REF_PROJECT`): baseline from the last release worktree
  with `tools/bytecompare.py baseline --repo <worktree>`, then
  `tools/bytecompare.py check --allow tools/bytecompare-allow.txt`; it renders a
  scratch copy and never writes into the reference project
- Ledger: `statutor-doctor .`; staged floor: `statutor staged .`
- Git floor setup (once per clone): `uvx pre-commit install`

## Non-negotiable engine rules

1. Behavior is pinned. Keep tests green and byte-compare `document.xml`,
   `styles.xml`, and `settings.xml` against the reference manuscript for render
   changes. Cosmetic-identical or documented/allowlisted differences only.
2. Correctness is unconditional `wongo.docxpatch` engine behavior. House taste
   belongs only in `src/wongo/styles/*.yml`; never blur those layers.
3. The reference manuscript uses wongo directly with `style: kist-wcr`; the
   former `quarto-manuscript-*` skills are wrappers, not canonical code.

## Conventions that differ from defaults

- Use `uv`, pytest, Python ≥3.11, SI units, and fish for user-facing shell snippets.
- `docs/docx-quirks.md` is compounding pathology memory: append root cause,
  affected versions, and raw-XML verification for every new DOCX quirk.
- `src/wongo/profiles/*/assets/reference.docx` is generated by its sibling
  script; never hand-edit it. Profile hard numbers require official sources.
- Keep output errors actionable; submission renders must fail before leaving a
  partial deliverable when a HARD gate fails.
- Windows is supported: raise `wongo.errors.WongoError` (never SystemExit),
  read sources with `wongo.textio.read_text`, decode subprocess output as UTF-8,
  and resolve executables through `wongo.toolchain`. The engine prints nothing;
  every command keeps `--json` output to one object (D-0008).
- Agent-instruction templates for scaffolded projects end in `.tmpl`; never add
  a file named like this repo's own agent files under `src/`.

## Pitfalls

- python-docx introspection can disagree with Word; verify OOXML in the ZIP.
- Rich paragraphs cannot safely be flattened by `wongo diff`; preserve and
  report them for Word Compare.
- A bare `uv run pytest` may resolve an external pytest before dev extras are
  synced; run setup or use the documented dependency-explicit command.

## Boundaries

- Do not edit `plans/archive/`; do not delete agent state or unrelated changes.
- `HANDOFF.md` is executor-owned and overwritten, never appended; max 40 lines.
- `TASKS.md` has one orchestrator writer and stable T-NNNN IDs.
- `DECISIONS.md` is append-only; supersede a choice with a new D-record.
- Subagents write task notes under `notes/`, not shared ledger files.
- `docs/CHANGELOG.md` is frozen historical context; use conventional commits and tags
  for future change history.
